## 1. Executive Verdict

Splitting the monolithic [specs.md](file:///mnt/devel/xosports/xo-scratchpad/edgepicks-redesign/specs.md#L1-L689) into three boundary-specific contracts plus an index ([overview.md](file:///mnt/devel/xosports/xo-scratchpad/edgepicks-redesign/staging/overview.md#L11-L26)) is a major structural improvement:
- **What passes 100%:**
  - All **5 JSON Schemas** (`snapshot.schema.json`, `producer-pick.schema.json`, `overlay-summary.schema.json`, `overlay-detail.schema.json`, `live-game-card.schema.json`) are valid JSON Schema Draft 2020-12 metaschemas.
  - All **6 JSON example payloads** across the suite validate with **0 errors** against their respective schemas.
  - All **33 test vectors** (`P-1`..`P-9` in [producers-to-bff.md](file:///mnt/devel/xosports/xo-scratchpad/edgepicks-redesign/staging/producers-to-bff.md#L186-L198), `E1`..`E13` and `D-1`..`D-11` in [bff-to-app-contract.md](file:///mnt/devel/xosports/xo-scratchpad/edgepicks-redesign/staging/bff-to-app-contract.md#L229-L265)) and every derived figure in the examples (`P1`, `G4`, day-summary rollups) recompute to exact `Decimal` precision.
- **What needs attention before publishing:**
  1. **Stale codebase claims (`nba_bet_engine` & `live-odds`):** Between the `16 Oct` commits cited in `staging/*.md` and `19 Oct 03:02Z` (when `staging/` was written), `nba_bet_engine@dev` advanced from `0a339e6` to `3bfbb8b`, removing probability smoothing, switching to flat `1.0u` props staking, disabling NBA player picks (`ps_picks_enabled: "false"` in `dev`/`tst`), and restricting game picks to spreads-primary (`top5_spreads_primary = true`). In `nfl_bet_engine`, depth-chart reconciliation (`_ps_reconcile.py`) is **reversible** (`Scheduled <-> cancelled`), which conflicts with `withdrawn` being a **terminal** state in [producers-to-bff.md](file:///mnt/devel/xosports/xo-scratchpad/edgepicks-redesign/staging/producers-to-bff.md#L30-L43).
  2. **JSON Schema vs. Prose gaps (violating Standard #3):** [overview.md](file:///mnt/devel/xosports/xo-scratchpad/edgepicks-redesign/staging/overview.md#L33) declares that the JSON Schema is the source of truth, yet 19 prose invariants (closed-world `additionalProperties: false`, pulled-price null cascades, `Selection` market/side/line rules in the BFF schema, `overlay_key` nullability, `Probability` `0`/`1` bounds) are missing from the schemas.
  3. **Cross-document & state-machine inconsistencies:** Minor contradictions exist between [bff-to-app-contract.md](file:///mnt/devel/xosports/xo-scratchpad/edgepicks-redesign/staging/bff-to-app-contract.md) and [producers-to-bff.md](file:///mnt/devel/xosports/xo-scratchpad/edgepicks-redesign/staging/producers-to-bff.md) around `cancelled` pick monitoring, `Probability` bounds, and `entry.edge` nullability.

   - `top5_spreads_primary = true` is now active in `_config.py` / `wltp_engine.py`: totals are only selected if a game has no spreads market, and moneyline (`H2H`) is suppressed for the early-season window (days 1–20).

### 2.2 `nfl_bet_engine`: Reversible depth-chart drops vs. terminal `withdrawn` state
- In [producers-to-bff.md](file:///mnt/devel/xosports/xo-scratchpad/edgepicks-redesign/staging/producers-to-bff.md#L30-L43), `withdrawn` is defined as **Terminal** (`open --> withdrawn`, `withdrawn --> [*]`).
- [producers-to-bff.md](file:///mnt/devel/xosports/xo-scratchpad/edgepicks-redesign/staging/producers-to-bff.md#L365) notes that [`_ps_reconcile.py`](file:///mnt/devel/xosports/github/nfl_bet_engine/src/bet_engine/_ps_reconcile.py#L1-L40) marks a pick `cancelled` when its player drops out of the depth chart and says *"this contract separates pre-game depth-chart drops into `withdrawn`"*.
- **Conflict:** In [`_ps_reconcile.py`](file:///mnt/devel/xosports/github/nfl_bet_engine/src/bet_engine/_ps_reconcile.py#L4-L14), depth-chart reconciliation is **reversible in both directions until kickoff** (*"A pick whose player has been ranked out of his position's top N is marked 'cancelled'; one whose player has climbed back in is restored to 'Scheduled'"*). Making `withdrawn` terminal in v4 means either (a) NFL can no longer reinstate a player who returns to the top N of the depth chart before kickoff, or (b) the state diagram needs a pre-kickoff `withdrawn --> open : player restored to depth chart` transition.

### 2.3 `live-odds@dev` (`30e05ce`): Orphaned RTDB nodes when `pick_id` changes across engine runs

- Neither [realtime-overlays.md](file:///mnt/devel/xosports/xo-scratchpad/edgepicks-redesign/staging/realtime-overlays.md#L49) nor [producers-to-bff.md](file:///mnt/devel/xosports/xo-scratchpad/edgepicks-redesign/staging/producers-to-bff.md#L35-L44) specifies how the monitor cleans up RTDB nodes when a producer replaces or withdraws a pick between runs.

   - In [producers-to-bff.md](file:///mnt/devel/xosports/xo-scratchpad/edgepicks-redesign/staging/producers-to-bff.md#L39-L44), the status table states *"the monitor stops"* for `awaiting_result` (line 39) and `withdrawn` (line 43), and [realtime-overlays.md](file:///mnt/devel/xosports/xo-scratchpad/edgepicks-redesign/staging/realtime-overlays.md#L49) says RTDB nodes are deleted when *"the pick stops being open"*, but the `cancelled` row in [producers-to-bff.md](file:///mnt/devel/xosports/xo-scratchpad/edgepicks-redesign/staging/producers-to-bff.md#L42) omits *"the monitor stops"*.
   - In [bff-to-app-contract.md](file:///mnt/devel/xosports/xo-scratchpad/edgepicks-redesign/staging/bff-to-app-contract.md#L200), the rule for `edge_state` says: *"The state is computed only while the pick is `open` and the game has not started; after that it stays at the value from the last observation before the start."*
   - Now compare [bff-to-app-contract.md Example 1, Pick 2](file:///mnt/devel/xosports/xo-scratchpad/edgepicks-redesign/staging/bff-to-app-contract.md#L484-L507): `status` is `"cancelled"`, `status_reason.code` is `"probability_moved"` (*"Our model no longer backs this pick"*), yet `model.probability` is still `0.48` (its entry probability, since `0.48 * 2.25 - 1 = +0.08` entry edge), while `current.odds.decimal` moved from `2.25` to `2.05`, giving `current.edge = -0.016` and `edge_state = "closed"`. Either:
     - The price moved from `2.25` to `2.05` (crossing `edge_holds_above = 2.0833`) **while the pick was still `open`**, and then the model pulled the pick on a later run (in which case a note explaining why `edge_state` is `"closed"` on a `"probability_moved"` cancellation would prevent confusion), **or**
     - If the model probability itself dropped and caused the cancellation, `model.probability` is frozen at entry ([producers-to-bff.md](file:///mnt/devel/xosports/xo-scratchpad/edgepicks-redesign/staging/producers-to-bff.md#L58)), so `current.edge` (`p_entry * d_current - 1`) does not reflect the new model probability anyway.
2. **Contradiction on when `entry.edge` can be `null` ([bff-to-app-contract.md](file:///mnt/devel/xosports/xo-scratchpad/edgepicks-redesign/staging/bff-to-app-contract.md#L94) vs. [line 210](file:///mnt/devel/xosports/xo-scratchpad/edgepicks-redesign/staging/bff-to-app-contract.md#L210)):**
   - [bff-to-app-contract.md](file:///mnt/devel/xosports/xo-scratchpad/edgepicks-redesign/staging/bff-to-app-contract.md#L94) says `entry.edge` is null when: *"`edge` hidden, or the producer sent none"*.
   - Yet [line 210](file:///mnt/devel/xosports/xo-scratchpad/edgepicks-redesign/staging/bff-to-app-contract.md#L210) (and [overview.md](file:///mnt/devel/xosports/xo-scratchpad/edgepicks-redesign/staging/overview.md#L64-L66)) specifies that `entry.edge` on the wire is always in EV units and **computed by the BFF from `p` and the entry decimal price**: $\text{entry.edge} = p \times d_{\text{entry}} - 1$. Even on legacy v1/v2 Cosmos docs where the producer sends no `entry_edge` field, the BFF has `probability` ($p$) and `decimal_odds` ($d_{\text{entry}}$). Thus `entry.edge` is only null when `edge` (or `odds`) is hidden, or if a legacy producer record is missing entry odds or probability altogether—not merely when the producer omits `entry_edge`.
3. **RTDB path format and scale constraints in [realtime-overlays.md](file:///mnt/devel/xosports/xo-scratchpad/edgepicks-redesign/staging/realtime-overlays.md#L139-L161):**
   - `overlay-summary.schema.json` ([lines 139–161](file:///mnt/devel/xosports/xo-scratchpad/edgepicks-redesign/staging/realtime-overlays.md#L139-L161)) uses `patternProperties` with `^[a-z]+$`, `^\d{4}-\d{2}-\d{2}$`, `^\d+$`, and `^[A-Za-z0-9_]+$`, which is clean and validates the example. However, because JSON Schema `patternProperties` without `"additionalProperties": false` allows non-matching keys to pass silently, any malformed key (e.g., `"2026/10/25"` or `"game_52901"`) at any of the 4 levels in `/edgePickStatus` will **not** fail validation unless `"additionalProperties": false` is added to each level of `overlay-summary.schema.json`.
